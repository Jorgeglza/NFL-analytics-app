## 2. Bugs

### B1 🔴 ✅ Home "This week" shows dates one day early
`app/src/pages/Home.tsx:32-34` does `new Date("2026-11-12")`. A date-only string is parsed as UTC
midnight, then formatted in local time, so in any timezone west of UTC it shows the previous day.
Reproduced (browser tz America/Mexico_City): Home says **"Week 10, 2026 — 14 games · Nov 11 – Nov 15"**;
the schedule says Nov 12 – Nov 16.
`WeekPreviewTab.tsx:223` already avoids this by appending `T12:00` — same fix applies here.

### B2 🔴 ✅ Stale "upcoming" predictions are presented as this week
`predictive_model/upcoming.json` is refreshed by its own workflow. Between a week finishing and
that workflow's next successful run, the file still holds the previous week. Nothing in the
frontend checks for that:

- `predictive-model/OverviewTab.tsx:68-71` shows **"This week — Season 2026, Week 9"** with the text
  "next scheduled-but-unplayed week", listing 14 games that were all played Nov 8–9.
- `spread-analytics/pickem/RecommendationsView.tsx:225-229` *prefers* `upcoming_meta`'s week over
  the schedule's current week, so Pick'em Recommendations opens on the finished week too.

This was live for ~2.5 days this week: the Tue Nov 10 scheduled `predictive-model-refresh` failed
and wasn't re-run until Nov 13 01:00 UTC (the retry fix in `1537f97`). Even on a good week there is a
gap every Monday night → Tuesday afternoon.
Suggested behaviour: compare `upcoming_meta.week` with `currentWeek(schedule)`; if it is behind (or
every listed game already has a score), label the block "Last week's predictions — refresh
pending" and let Pick'em fall back to the schedule's week.

### B3 🟡 ✅ Mobile nav menu can't be scrolled
`components/Navbar.tsx` — the open menu makes the sticky header 678 px tall with no
`max-height`/`overflow-y`. Measured:

- 375×667 (iPhone SE/8 size): header 678 px vs 667 px viewport — the last link sits at 662 px, i.e.
  under the browser's bottom toolbar on a real phone.
- 667×375 (landscape): the last link is at 662 px in a 375 px viewport. Because the header is
  `sticky`, scrolling the page doesn't move it; the Player Analysis and Data links only come into
  view at the very bottom of the page.

Also missing: `aria-expanded` on the hamburger and the desktop dropdown buttons, Escape-to-close,
and body-scroll lock while the menu is open.

### B4 🟡 ✅ Team Comparison rewrites the shared week
Fresh load → Game Picks opens on Week 10 (correct, the upcoming week). Open Team Comparison, go
back → Game Picks is now on **Week 9**. Team Comparison's week-fixing effect snaps to the latest week
that has stats and writes that into `SeasonWeekContext`, which Game Picks, Weekly Breakdown and
Season Outlook all read. Scorecards, Prop Bets, Season Outlook and Weekly Breakdown do not cause it.
A page that needs "latest week with data" should keep that as a local, derived value instead of
writing it to the shared selection.

### B5 🟡 ✅ Info-dot popovers clipped on phones
`components/InfoDot.tsx` centres a 256 px popover on the dot (`left-1/2 -translate-x-1/2`). When
the dot is near either edge the popover runs off-screen and the root's `overflow-x-clip` cuts the
text. At 375 px: 4 of 5 popovers on Win Rate & Calibration and the one on Team Comparison are
clipped.

### B6 🟡 ✅ Unknown URL renders a blank page
`App.tsx` has no `path="*"` route. `#/nope` (or any mistyped/stale bookmark) shows the navbar and
an empty white page; console logs "No routes matched". There is also no React error boundary, so
a render exception in any page blanks the whole app the same way.

### B7 🟢 ✅ Matchup Bets has no tab title
`/player_analysis/matchup_bets` shows "NFL Analytics" as the document title — it isn't in
`NAV_GROUPS`, has no entry in `TITLE_OVERRIDES` and doesn't call `usePageTitle`.

### B8 🟢 ✅ React warning in TabBar on every tabbed page
`components/TabBar.tsx` builds `{ key, onClick, className }` and spreads it into JSX. React logs
"A props object containing a "key" prop is being spread into JSX" on Spread Analytics, Season
Outlook, Grading Model, Predictive Model, Model Backtest and Matchup Previews. Harmless today,
noisy in the console.

### B9 🟢 📖 Kickoff time shown without a timezone
`previews/MatchupTab.tsx:1200` formats `gameday` + `gametime` as if it were local time. nflverse
`gametime` is US Eastern, so a 13:00 ET kickoff reads "1:00 PM" in Monterrey (really 12:00 or
11:00 depending on DST). Either label it "ET" or convert.

### B10 🟢 📖 Modal steals focus back on parent re-render
`components/Modal.tsx` puts `onClose` in its effect deps and focuses the close button every time
the effect runs. `MatchupTab.tsx:1534` passes an inline `onClose={() => …}`, so any re-render of
the Matchup tab while that modal is open re-runs the effect and yanks focus to ✕. The other eight
modal call sites pass a stable prop and depend on their parents doing the same.

### B11 🟢 📖 A few loads have no error path
`grading-model/TeamsTab.tsx:45`, `WinTypeDetailModal.tsx:124`, `RecommendationsView.tsx:208-209`,
`ThisWeekView.tsx:786`, `ParlayBuilder.tsx:95` and `SeasonWeekContext.tsx` call `.then()` with no
`.catch()`. On a dropped connection these become unhandled rejections; the Teams tab would just
stay empty with no Retry. `GamePicks.tsx:185` also calls `localStorage.setItem` outside a
try/catch (the read is guarded, the write isn't).

### B12 🟢 ✅ Repo hygiene
- Untracked, empty `package-lock.json` at the repo root (someone ran `npm` one level too high).
- `.git/objects/pack/tmp_pack_FN739l` — 17 MB of garbage from an interrupted fetch
  (`git count-objects` reports it). `git gc --prune=now` clears it.
- Local `main` is 1 commit behind `origin/main`.

## 3. Model / analytics correctness

These are not crashes; they affect how much the numbers can be trusted.

### M1 🟡 📖 Model Backtest: two models see the future
`lib/logic/backtest.ts` replays `probBundle()` for every historical game. Elo, Pythagorean and
the Predictive model are genuinely pre-game. Two are not:

- **Market-calibrated** — `engine.ts:marketRate()` excludes only the game's own season-week from
  the bucket's historical favourite-win rate. A 2016 game is therefore scored with 2017–2026
  outcomes in the bucket.
- **Trend Edge** — uses season-to-date grades, but those grades come from Random Forests fitted
  once on *all* seasons and min-max scaled over the whole dataset (`pipeline/nfl_pipeline/grading.py`).
  The weights behind a 2016 grade already "know" 2017–2026.

Both effects are probably small, but they bias ROI/accuracy upward, and the Consensus model
inherits them. The Methodology tab's caveats list doesn't mention it. Minimum: add the caveat.
Better: an "as-of" bucket rate (only games before the one being scored).

### M2 🟢 📖 Playoff odds change on every visit
`lib/logic/playoffSim.ts` uses `Math.random()` with 2,000 iterations. Standard error at 50% is
about ±1.1 points, so a team can read 47% now and 49% a minute later with no new data, and the
table and the detail modal (each with its own `ITERATIONS = 2000`) aren't guaranteed to agree.
A seeded PRNG (seed = season + week) makes results reproducible and shareable.

### M3 🟢 📖 Neutral-site games get home-field advantage
`lib/logic/elo.ts:eloPHome` always adds +48 Elo for the listed home team. `schedule.json` has a
`location` column (Home/Neutral) that is never read, so international games and the Super Bowl
are treated as true home games in Elo, Power Rankings, Strength of Schedule and the playoff sim.

### M4 🟢 📖 Playoff tiebreak comparator isn't transitive
The pairwise comparator in `playoffSim.ts` (win% → head-to-head → conference record → point diff)
can cycle in a three-way tie (A beat B, B beat C, C beat A), and `Array.sort` with a non-transitive
comparator gives engine-dependent order. Already documented as "simplified"; mentioning it because
it mostly affects exactly the close races people look at.

## 4. Pipeline and automation

### P1 🔴 📖 A failed fetch of the current season is treated as "not published yet"
`pipeline/nfl_pipeline/fetch.py:fetch_weekly` and `fetch_schedules` skip the newest season with a
warning on *any* exception — designed for August, before the season exists. In November the same
branch fires on a network blip. CI always runs with `--refresh` on a clean runner, so there is no
cache to fall back on: 2026 would vanish from `team_week`, `meta.seasons` (derived from
`team_week`) would end at 2025, `--stage validate` would pass (it allows one season behind), and
the site would auto-commit and deploy without the current season.
Suggested: add the same retry wrapper `predictive_model/fetch.py` got in `1537f97`, and have
`validate` fail if the newest season in the *schedule* has played games but no `team_week` rows,
or if a season present in the previous `meta.json` is now missing.

### P2 🟡 ✅ CI gaps
- `deploy.yml` runs `npm ci` + `npm run build` only. The 62 vitest tests never run in CI, and
  `pipeline/tests/` is empty.
- Neither refresh workflow has a `concurrency:` group. Both commit to `main`; if they overlap, the
  second push is rejected and that run fails. Scheduled starts have been close before (Nov 10:
  14:46 and 16:21 UTC; Nov 3: 14:02 and 16:06).
- Both workflows repeat a hand-typed `pip install` list instead of `pipeline/requirements.lock.txt`,
  and `joblib`, `scipy`, `appdirs`, `fastparquet` are unpinned — relevant because grade
  reproducibility depends on pinned versions.

### P3 🟡 ✅ Scheduled runs start 5–9 hours late
Configured: weekly refresh 01:07 ET (≈06:07 UTC); predictive Tue 08:07 UTC / Fri 18:00 UTC.
Actual starts in November: weekly 14:02–16:03 UTC, predictive Tue 16:06–16:21 UTC, Fri 22:55 UTC.
October was 4–5 hours late. So Monday-night results reach the site around 9–10 am Monterrey on
Tuesday, not overnight. That's GitHub's scheduler, not your config — but if overnight freshness
matters, a `workflow_dispatch` triggered from an external cron is the reliable route.

### P4 🟢 📖 Smaller items
- `validate` checks counts > 0, season range and grade bounds only. Cheap additions: no duplicate
  `(season, week, team)` in the current season, latest played week present in `team_week` and
  `grades`, no played game with a null spread.
- `--refresh` re-downloads all 12 seasons three times a week; only the current season changes.
- `.git` is 214 MB after 308 commits, mostly from committing the 39 MB `data/nfl.sqlite` on every
  refresh, inside OneDrive. See Open questions.
- `predictive_model/game_features.json` is 2.5 MB and each `player_week/<season>.json` ~2 MB raw.
  `loader.ts` gives every file a 15 s timeout and restarts from zero on retry — tight on a slow
  mobile connection.

## 5. Mobile and accessibility

**What's good:** zero horizontal page overflow on all 24 routes at 375 px and 768 px; wide tables
scroll inside their own container; modals become bottom sheets with scroll lock and focus trap;
filter sheets exist; range-slider thumbs enlarge on touch; safe-area padding is in place.

### A1 🟡 ✅ Tap targets below 44 px (phone, 375 px)
| Page | Control | Size | Count |
|------|---------|------|-------|
| Matchup Previews (Week Preview) | per-model "details" dots | 24×24 | 86 controls under 32 px |
| Season Outlook → Power Rankings | "Compare" | 71×26 | 32 |
| Value Bets | "Zoom in →" | 54×17 | 16 |
| Team Scorecard | "A" toggles | 24×24 | ~17 |
| Player Team Stats | leaderboard rows | 317×24 | 10 per card |
| Build Parlay | offense / defense chips | ~60×24 | 2 per leg |
| every page | info dot "i" | 20×20 | 1–5 |
| Matchup Bets | "← Back to Value Bets" | 113×16 | 1 |

The dense Matchup Previews strip is the one that actually causes mis-taps.

### A2 🟡 ✅ Very small text
Leaf text nodes under 11 px at phone width: Team Scorecard 123, Team Comparison 101, Pick'em 96,
Matchup Previews 68, Game Picks 61. Source has 104 × `text-[10px]`, 23 × `text-[9px]`,
7 × `text-[8px]`, 1 × `text-[7px]`. Anything under 10 px is hard to read on a phone; 11 px is a
reasonable floor for labels.

### A3 🟡 📖 Low-contrast grey
`text-slate-400` (#94a3b8 on white ≈ 2.6:1) is used 312 times, mostly on the small uppercase
labels and captions; `text-slate-300` 14 times. WCAG AA needs 4.5:1 for small text.
`text-slate-500` (≈4.8:1) passes with almost no visual change.

### A4 🟡 📖 Hover-only explanations
283 `title="…"` attributes carry real explanations (model definitions, what a number means).
`title` never shows on touch. `InfoDot` already solves this where it's used — the highest-value
`title`s (KPI definitions, Game Picks badges, model chips) are worth converting.

### A5 🟢 📖 Keyboard / screen-reader gaps
- Clickable table rows with no keyboard path: `PlayoffTab.tsx:68`, `PowerRankingsTab.tsx:72`,
  `MatchupBets.tsx:584`, `PropBets.tsx:337` (`<tr onClick>`, no `tabIndex`/Enter handler).
- Charts (ECharts canvases) have no `aria-label` or text alternative.
- `TabBar` buttons don't expose `role="tab"`/`aria-selected`.
- Two unlabeled controls: one on Win Rate & Calibration, one on Glossary.
- No `prefers-reduced-motion` handling (hover lifts, spinners, chart animations).

### A6 🟢 ✅ ECharts zero-size warnings
"Can't get DOM width or height" logged ~14 times per sweep — charts initialised inside
not-yet-laid-out containers. The `requestAnimationFrame` resize in `useECharts.ts` recovers, so
nothing is visibly broken; it was observed with the preview pane hidden, which may inflate the count.

## 7. Feature recommendations

Ordered by value for effort. Everything in the first group needs **no new data**.

**Uses data already exported**

1. **Season-long pick tracker.** Game Picks stores your picks and scores them per week. Add a
   season view: your record by week, running total, and the same weeks scored for "always
   favourite", "always home" and each model — "am I beating the models?" in one chart.
2. **Totals (over/under) analytics.** `schedule.json` has `total`, `total_line`, `over_odds`,
   `under_odds`; they're read in only two places. An Over/Under tab next to Win Types — over rate
   by total bucket, by team, by roof/weather — mirrors the spread analysis you already have.
3. **Situational splits.** `roof`, `surface`, `temp`, `wind`, `away_rest`/`home_rest`, `div_game`
   and `referee`/coach columns are exported but unused in the UI. Favourite win rate and ATS by
   rest advantage, divisional vs not, dome vs outdoor, short week.
4. **ATS standings.** `engine.ts` already builds per-team cover history for the ATS-trend input.
   Surface it: each team's ATS record, home/away and favourite/underdog splits, current streak.
5. **Global team/player search** in the navbar that jumps to Team Scorecard / Prop Bets with the
   selection applied (the deep-link params mostly exist).
6. **Shareable URLs everywhere.** Game Picks and Team Comparison read `?season=&week=`; most other
   pages keep filters in component state only, so a view can't be bookmarked or sent to someone.
7. **CSV export** next to the existing copy-as-image on tables.
8. **"What changed this week" digest on Home:** biggest Power Rankings movers, biggest playoff-odds
   swings, last week's model record. All computable client-side from what's loaded.
9. **Model track record on the current week.** On Week Preview, show each model's season-to-date
   record beside its pick, so "which model do I trust this week" doesn't need a trip to Backtest.
10. **Playoff "what if".** Let the user force results for remaining games in the Monte Carlo and
    see the odds move. The sim already takes played/remaining lists.

**Platform**

11. **Installable PWA + offline.** There's no web manifest or service worker. The app is fully
    static, so caching the JSON makes it installable on a phone and usable with no signal — a
    good fit for game day.
12. **Dark mode.** No `dark:` classes or `prefers-color-scheme` handling exist; a common request
    for a second-screen app used at night.
13. **Spanish/English toggle**, if anyone besides you uses it.

**Would need new data — listed for completeness; you've said no new imports**

14. Live in-game scores, injury report surfaced on Matchup Previews (the predictive package
    already pulls injuries for its own features), historical prop lines for a real Value Bets
    backtest.
